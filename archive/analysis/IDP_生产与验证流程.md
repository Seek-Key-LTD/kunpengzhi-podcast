## 二、验证闭环（三层验证 + 重跑）

```mermaid
flowchart TD
    G[九段生成] --> V1{结构验收<br/>九段全到?}
    V1 -- 缺段 --> R1[只重跑缺失段]
    R1 --> G
    V1 -- 通过 --> V2{论证覆盖<br/>必进论证 100%?}
    V2 -- 缺论证 --> R2[只重跑缺失论证所在段]
    R2 --> G
    V2 -- 通过 --> V3{红队评审<br/>商业标准}
    V3 -- 硬伤<br/>史实错误/伪造引文 --> R3[修订该段]
    R3 --> G
    V3 -- 软问题<br/>爆点不足 --> R4[修订建议]
    R4 --> V3
    V3 -- 无硬伤 --> E[验收报告]
    E --> U{用户终审}
    U -- 过 --> P[进生产<br/>播客生成]
    U -- 不过 --> R5[按意见修订]
    R5 --> G
```

## 三、判定标准（可判定、可复现）

| 层 | 判定 | 不过怎么办 |
|----|------|-----------|
| 结构验收 | 九段 9/9，每段 ≥400 字 | 只重跑缺失段 |
| 论证覆盖 | 必进论证 100% 命中 | 只重跑缺失论证所在段 |
| 红队评审 | 无硬伤（史实错误/伪造引文）| 修订该段；软问题给建议 |
| 用户终审 | 你说了算 | 按意见修订 → 重新走验证 |

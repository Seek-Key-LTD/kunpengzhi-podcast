# 飞书知识库同步说明（给别人看的操作手册）

本仓文稿与飞书知识库**双向同步**。任何人照本文即可读、写、排查。

## 0. 先认清一件事（最容易踩的坑）

目标知识库是**公开知识库（public wiki space）**，这意味着：

- **不能靠"加成员"授权**——公开空间调用 `wiki +member-add` 会报 `131101 public wiki space can't create member`；
- **应用（tenant/bot）身份写不进去**——报 `131006 tenant needs edit permission`，就算把应用设成所有者也不行；
- **只有"用户身份"（user_access_token）能写**。

所以别用 `--as bot` 去改知识库，一定用 `--as user`。

## 2. 授权（一次性，主机无浏览器也没关系）

设备码授权**不需要在主机上开浏览器**，授权在手机/电脑完成即可：

```bash
# 配应用（profile 名 n8n-cli）
printf '%s' "$APP_SECRET" | lark-cli config init \
  --app-id cli_a96ae027b1fc5bc0 --app-secret-stdin --brand feishu --name n8n-cli

# 发起授权（务必 --domain all，别收窄）
lark-cli --profile n8n-cli auth login --domain all --no-wait --json
#   → 拿 verification_url 去浏览器/手机确认
lark-cli --profile n8n-cli auth login --device-code '<上一步的 device_code>'
```

profile 落在 `~/.lark-cli`；lark-cli 会自行续期短期凭证。

**跑在哪**：这类任务用 **raccoon / luban** 节点，**别用 pve**（pve 的 runner 以 root 跑、home 不可写、无 sudo）。
raccoon 的 gitea-runner 以 `ben` 运行、`HOME=/home/ben` 可写、已装 `/usr/local/bin/lark-cli`，`runs-on: [raccoon]` 的 job 能直接用该 profile。

## 3. 同步脚本

`scripts/sync_feishu_wiki.py`

```bash
python3 scripts/sync_feishu_wiki.py                      # 仓库 → 飞书（主线）
python3 scripts/sync_feishu_wiki.py --include-spinoff    # 仓库 → 飞书（含番外）
python3 scripts/sync_feishu_wiki.py --pull               # 飞书 → 仓库（写入工作区）
python3 scripts/sync_feishu_wiki.py --baseline           # 只记当前 revision 基线，不拉正文
python3 scripts/sync_feishu_wiki.py --dry-run            # 只看计划
```

状态文件 `scripts/feishu_wiki_state.json`：每条记 `node_token / obj_token / sha256 / revision_id`。
- 仓库文件 `sha256` 变了 → 推
- 飞书 `revision_id` 变了 → 拉（冲突时**飞书优先**）

```bash
# 看一眼能不能读正文（证明权限没问题）
lark-cli --profile n8n-cli docs +fetch --doc <node_token> --doc-format markdown --as user --format json | head -c 400

# 列容器子节点（注意：CLI 的 +node-list 有时返回 0，用原始 API 更稳）
lark-cli --profile n8n-cli api GET /open-apis/wiki/v2/spaces/7692783315471846383/nodes \
  --params '{"parent_node_token":"XBgZw3UvBiH8AOkXpH9cQYVjnkf","page_size":50}' --as user --format json
```

**已知代价**：飞书导出的 markdown 与仓库原文有**系统性格式差异**（行尾硬换行丢失、引用块变 `> >`、空行处理不同）。被"拉回"过的文档格式会变成飞书风格——这是飞书导出行为，绕不开。
